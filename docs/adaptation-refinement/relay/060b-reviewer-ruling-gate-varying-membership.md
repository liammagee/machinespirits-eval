# 060b — Reviewer ruling: menu membership is gate-varying injection

**Date:** 13 August 2026. Answers the second session's point 3 on
note 060a (the four instructional-meta renderer lines) and corrects
note 060a item 6. Zero calls; the HOLD stands.

## The membership test

Amendment 1 §1 reads "every instruction string the gate decision
can cause to be injected … Nothing else." Registration §2 defines
the standing-permission condition as **the bare stub plus** the
standing text. So any string the bare stub also renders live
appears in every condition already; quoting it in the menu adds
standing text only to the standing condition, an additive
difference the contrast does not want. And any gate-varying string
missing from the menu denies the standing condition words the
gated condition gets, which breaks the isolation purpose directly.

**A string is IN if and only if its injection can vary with the
gate decision** — the gate being present, or deciding differently,
can change whether or which string renders. The gate's decision
path is the gate verdict, the repair policy, and the register
selection downstream of it. Strings switched only by variables
that path cannot touch (learner-wording classification, world
state, progression bookkeeping identical across conditions) render
the same in bare and standing live, and stay OUT.

Ruling 059a's no-pruning rule is unchanged and applies WITHIN the
gate-varying surfaces: every stance, action family, tactic, part,
and support selection the policy can make sweeps in mechanically.

## Applications

1. **Instructional-meta lines (renderer lines 909–920): OUT.** The
   plane is set by the learner-analysis classifier from the
   learner's own wording, upstream of the gate; all four lines
   render identically in the bare condition.
2. **Note 060a item 6 is corrected.** The opening-instruction
   branch literals are candidates, not automatic members. Each
   one's membership follows the trace of its switching variable —
   for example, the "Write:" branches switch on the learner's
   writable-entry request, and if the gate's decision path cannot
   reach that switch they are out.
3. **The enumeration rule must show the classification.** For
   every candidate string: its switching variable, whether the
   gate's decision path can reach it, and the verdict. Where the
   trace is uncertain, include the string and record the doubt —
   the additive error is smaller than the missing-words error.

The review of report 061 applies this test on top of the 060a
checklist. A menu that swept in non-gate-varying strings under
direction 060's broader wording is one zero-call send-back, not a
defect — the direction preceded this ruling.
