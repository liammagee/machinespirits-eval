## Pin 1 — measure 1's computation path (readers, planned calls)

The "binary consensus" layer in the arc record is a two-reader
consensus layer, not a log parse. Measure 1 is therefore: the stub's
observe-arm decision, parsed deterministically from run logs, scored
against the binary consensus of two FRESH independent readers using
the same frozen binary decision instrument as the last diagnostic
checkpoint, digest-pinned in the A1 manifest. Consensus cases only;
non-consensus cases are excluded and counted in the report. These
reader calls are separate from the presence readers and MUST appear
in each phase's planned call count before any call: per phase,
planned readers = 2 × cases for presence PLUS 2 × decision cases for
the binary layer.

## Pin 2 — saturation denominator for measures 7 and 8

Measures 7 and 8 are per-case. For them, registration §6(b) reads
"cases" where it says "dialogues": the denominator is consensus
cases pooled across conditions; a non-consensus or inadmissible case
leaves the denominator. A dialogue may contribute more than one case
only if the extraction rule recorded in the A1 manifest says so; the
manifest states the rule and the expected case count. Measures 1-6
keep the dialogue denominator as written.
