## Root cause

The B1 design named `world_031_orchard_clinic`,
`world_035_harbor_scheduler`, `world_038_waterworks_mark`, and
`world_041_north_joint`. Those IDs do not exist in the launch commit. The
zero-call compiler exercised action, register, scene, question, persona, and
safety behavior but did not resolve every registered world through the live
scenario catalog. The launcher also treated a failed child as a returned row
without halting the remaining queue.

The correction is fixed independently of these partial outputs: use the exact
v8 set `world_022_foxtrot_jukebox`, `world_026_skyway_bakery`,
`world_028_larkspur_fridge`, `world_029_riverside_clinic`,
`world_030_rowan_flat`, and `world_031_tideway_makerspace`. This is the set
whose sealed transcripts supported P0 and whose prospective window audit
already established two on-path public premises by the earliest endpoint.

## Rejected options

- Reuse the four partial dialogues: rejected because none completed and the
  corrected design changes the registered world set.
- Resume the existing destination: rejected because it is create-once evidence
  for a source-bound failed launch.
- Substitute valid world names only at the CLI: rejected because the launch
  commit must contain the exact corrected design.
- Continue R1 under the old GO: rejected because the operator authorized one
  combined launch and the launcher was stopped before R1 began.
- Inspect partial public turns to choose worlds: rejected. The v8 world set was
  fixed from the prior registration and channel audit, not from this attempt.
