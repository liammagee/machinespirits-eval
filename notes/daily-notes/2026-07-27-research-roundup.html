Prompt Engineering

Two-Level Meta-Rubrics for Evaluating Open-Ended Generation: GAMUT, a Benchmark for Factual Completeness UNBLOCK

Xilun Chen, Zhaleh Feizollahi, Ross Goodwin, Seungwhan Moon, Scott Yih, Pinar Donmez, Babak Damavandi, Luna Dong · arXiv 2607.19322 · July 21, 2026 · https://arxiv.org/abs/2607.19322

Argues that factuality evaluation for long-form generation has over-indexed on precision (are the claims correct?) while neglecting completeness (does the response contain everything it should?), which is harder to grade because the "should-contain" facts rarely form a flat checklist — they involve open-ended coverage sets, ordered processes, and inter-fact relationships a list of independent boolean checks can't capture. GAMUT introduces two-level meta-rubrics as a structured grading unit for exactly this kind of non-flat completeness criterion.

Project relevance: Directly on-target for the v2.2 rubric's own judge design (config/evaluation-rubric*.yaml) and for the poetics rubric (config/evaluation-rubric-poetics.yaml), both of which already ask LLM judges to grade non-flat, order-and-coverage-sensitive criteria (did the tutor's turn incorporate the superego's specific critique? did the drama's anagnorisis actually resolve the ledger, not just gesture at it?) with flat per-dimension Likert prompts. GAMUT's two-level meta-rubric structure — a rubric for generating the checklist, then a rubric for grading against it — is a concrete template for tightening `content_accuracy` and the poetics dimensions against exactly the completeness failure mode the paper identifies, rather than continuing to rely on single-shot judge prompts.

Agent Architecture

OpenForgeRL: Train Harness-native Agents in Any Environment UNBLOCK

Xiao Yu, Baolin Peng, Ruize Xu, Hao Zou, Qianhui Wu, Hao Cheng, Wenlin Yao, Nikhil Singh, Zhou Yu, Jianfeng Gao (Columbia, Dartmouth, Microsoft Research) · arXiv 2607.21557 · July 23, 2026 · https://arxiv.org/abs/2607.21557

Observes that modern agents lean on elaborate inference harnesses — the paper names Claude Code and Codex explicitly — to drive multi-turn reasoning, tool use, and external-system access, but that these stateful, multi-process harnesses are hard to train end-to-end because open SFT/RL stacks can't natively express them. OpenForgeRL's fix is a lightweight proxy that serves the harness's own model calls while recording them as RL training data (feeding a standard codebase like veRL), plus a Kubernetes orchestrator that runs each rollout in an isolated remote container — training directly on the real harness rather than a simplified stand-in.

Project relevance: A close structural match for the project's own CLI-bridge architecture (`--ego-model codex.gpt-5.5` etc. reaching tutor-core's dialogue engine via tutor-core/services/externalAIProvider.js) and for `services/adaptiveTutor/`'s LangGraph runner — both are exactly the kind of "harness the model calls flow through" that OpenForgeRL's proxy pattern targets. Most directly relevant to any future move from hand-tuned prompt/mechanism ablation (the current cells 1-125 factorial) toward RL-trained tutor policies: OpenForgeRL is a plausible infrastructure choice for training an ego or superego policy end-to-end inside the actual dialogue-engine harness instead of a simplified proxy environment.

PRO-LONG: Programmatic Memory Enables Long-Horizon Reasoning WATCH

Alexis Fox, Junlin Wang, Paul Rosu, Bhuwan Dhingra · arXiv 2607.20064 · July 22, 2026 · https://arxiv.org/abs/2607.20064

Frames long-horizon agent performance as bottlenecked by a context-management tradeoff: saving more environment history helps recall but makes it less tractable to retrieve the relevant parts. PRO-LONG resolves this by keeping a complete structured interaction log and using a coding-agent-style search over it rather than compressing or truncating; on ARC-AGI-3 it beats a base coding agent by 18 points and matches specialized harnesses while using 4.2-5.8x fewer tokens.

Project relevance: Background interest for `services/adaptiveTutor/stateSchema.js` and `persistence.js`, which already keep a persisted per-turn state log for counterfactual replay (cell 110's `state_policy` architecture) — PRO-LONG's "search the full structured log instead of compressing it" strategy is an alternative to whatever summarization/pruning the adaptive runner currently does over long trap-scenario dialogues, worth checking against as multi-turn scenarios grow (cells 111-113, 124).

Dramaturgy / Role-Play

Mitigating Scaffolding Collapse in Socratic Tutors via Representation Alignment UNBLOCK

Jing Shao, Qifeng Wu, Hanyu Zhang, Sixia Sun, Jun Zhuang · arXiv 2607.19371 · July 2026 · https://arxiv.org/abs/2607.19371

Names and studies exactly the failure mode this project calls dogmatic/dialectical breakdown: under sustained student pressure, an LLM Socratic tutor gradually abandons guided inquiry and reveals the answer directly — "scaffolding collapse." The paper's diagnosis is that prior defenses (prompting, preference optimization, output filtering) only constrain the visible response, leaving the internal representation drift that precedes trajectory-level collapse unaddressed; its fix, Scaffold-Preserving Representation Alignment, warms up with SFT then adds trajectory-weighted DPO plus a margin-preserving representation loss anchored to frozen reference states, so the tutor's internal "staying in role" signal is trained directly rather than only its surface text.

Project relevance: This is close to a formal, mechanistic account of what the dogmatic-protocol-control drama family (today's Drama of the Day pool; `condition: dogmatic_routine_control`, `mismatched_rhetorical_dramatic_plan`) is probing behaviorally: does the tutor hold its Socratic role — refusing to just confirm the number and sign off — under a learner pushing for closure? Where this project measures collapse post hoc via the poetics rubric (`config/evaluation-rubric-poetics.yaml`) and the trap-scenario suite (cells 110-125), this paper offers a training-time, representation-level intervention that could be read as a proposed mechanism variant: a superego or ego objective that penalizes representation drift toward "reveal" states specifically, rather than only critiquing the final text as the current divergent-superego cells (22-33) do.

Rhetoric

Beyond Sycophancy: Structured Resistance and Compliance in LLM Moral Reasoning UNBLOCK

Baihui Wang, Bernard Koch · arXiv 2607.21558 · July 23, 2026 · https://arxiv.org/abs/2607.21558

Reframes sycophancy as one expression of a broader judgment-updating process rather than a single failure mode: across three studies, models' willingness to revise a moral judgment under incoming social pressure is structured along three dimensions that mirror human social psychology — distance between the incoming view and the model's initial position, the attributed source of that view, and the coalition structure behind it. Models are more receptive to nearby positions, more swayed by views framed as their own prior judgments, and respond differently to group pressure than to a single dissenter.

Project relevance: Directly relevant to the divergent-superego cells (22-33, `config/tutor-agents.yaml`), which manipulate the superego's critique register (suspicious/adversary/advocate) and depend on the ego resisting or incorporating that critique in a principled way rather than simply yielding to it. This paper's three-dimensional resistance-compliance framework — distance, source attribution, coalition — is a candidate lens for `services/dialogueTraceAnalyzer.js`'s superego-feedback-incorporation analysis: rather than a single incorporation-rate number, ego revisions could be classified by *why* the ego moved (was the superego's critique close to the ego's own position? was it framed as the ego's own prior reasoning reflected back? did the "advocate" vs "adversary" register function like a coalition size manipulation?).
