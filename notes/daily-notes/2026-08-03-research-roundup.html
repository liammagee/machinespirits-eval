Prompt Engineering

AISPA: User-Centric System Prompt Auditing for Large Language Model Applications UNBLOCK

Xiangning Lin, Shenzhe Zhu, Shu Yang, et al. (Stanford, CMU, UT Austin, Toronto, and others) · arXiv 2607.28617 · July 30, 2026 · https://arxiv.org/abs/2607.28617

Argues that system prompts govern how commercial AI products behave but are almost never disclosed, leaving no way for users or regulators to check what they actually instruct. AISPA is a user-centric audit framework that scores individual instructions in a system prompt along eight dimensions — identity transparency, information truthfulness, data privacy, action safety, user agency, unsafe-request handling, harm prevention, and fairness/neutrality — and applies it to 3,249 instructions pulled from 88 commercial products, sorting each into protective or problematic.

Project relevance: A ready-made checklist for auditing this project's own prompt files (`prompts/tutor-ego*.md`, `prompts/tutor-superego*.md`, the placebo/recognition/enhanced variants) the way `cell-config-auditor` already audits cell YAML: does the recognition prompt's language around "autonomous subject" read as user-agency-respecting rather than manipulation-adjacent, does the placebo control actually match the recognition prompt on AISPA's eight axes rather than only on length? Eight independently-scored dimensions per instruction is also a concrete template for tightening the placebo-vs-recognition 3-way comparison beyond a length/complexity match.

Agent Architecture

Scaling LLM-Driven Multi-Agent Systems: Design Principles and Architectural Scalability Analysis UNBLOCK

Linus Sander, Fengjunjie Pan, Vahid Zolfaghari, Andre Schamschurko, Nenad Petrovic, Alois Knoll · arXiv 2607.27942 · July 30, 2026 · https://arxiv.org/abs/2607.27942

Notes that the design space for LLM multi-agent systems is still unsystematized and that scalability is only partly understood, then distills four design principles for architectures that actually scale: simplicity, elastic feedback, sequential workflows with optional loops, and summary-based communication. It formalizes a reference architecture as a constrained directed workflow graph and benchmarks four configurations of increasing complexity across two model tiers, finding run-to-run consistency — not accuracy or cost — is the open problem for production-grade systems.

Project relevance: A direct check against the project's own bilateral ego-superego loop and the LangGraph-based `services/adaptiveTutor/graph.js`: both already lean on "sequential workflow with an optional loop" (ego generates, superego critiques, ego revises) and summary-based handoff between turns. The paper's naming of run-to-run consistency as the central open problem matches a live concern for the trap-scenario suite (cells 110-125), where the same scenario under the same cell can still produce a dogmatic-collapse trajectory on one run and a clean recognition on the next — worth reading against whatever variance the adaptive runner's mock vs real LLM paths already show.

Σ-Mem: An Online Reliability Memory for LLM-based Multi-Agent Systems WATCH

Peilin Feng, Suorong Yang, Soujanya Poria · arXiv 2607.27958 · late July 2026 · https://arxiv.org/abs/2607.27958

Proposes a memory that tracks two things across a multi-agent system's lifetime without retraining any model: each agent's historical competence record, and pairwise relationship records between agents, both updated online from correctness feedback after each decision. Early results show reading directly from this reliability memory beats standard coordination approaches on stability.

Project relevance: Background interest for `services/dialogueTraceAnalyzer.js`'s superego-feedback-incorporation tracking and the bilateral `adaptationIndex`/`learnerGrowthIndex` measures — both are already informal versions of a per-agent, per-relationship reliability record (does this ego tend to incorporate this superego's critiques?), computed post hoc per run rather than maintained online across turns. Worth checking whether an online reliability signal changes anything for the divergent-superego cells (22-33), where the superego's register (suspicious/adversary/advocate) is exactly the kind of per-relationship variable this paper's memory is built to track.

Dramaturgy / Role-Play

Beyond Borrowed Histories: Person-Aligned User Simulation for Interactive Role-Playing Evaluation UNBLOCK

Yuhang Zhu et al. · arXiv 2607.27816 · July 30, 2026 · https://arxiv.org/abs/2607.27816

Points out that most role-playing-agent benchmarks make the agent continue a fixed, borrowed dialogue history and then grade the continuation with a rubric detached from any particular user — which can't tell you how the agent behaves across a real multi-turn relationship. PALATE fixes this by generating personalized user profiles, running five per-user simulators through free-form multi-turn conversations with the candidate agent, and separately scoring generic turn quality, long-horizon session capability, and per-user experience with personalized rubrics.

Project relevance: Close to a formal statement of a standing design choice in this project: the learner is not scripted but a full ego-superego LLM agent (`services/learnerTutorInteractionEngine.js`) precisely so evaluation isn't graded against a borrowed, fixed history. PALATE's three-way split — generic turn quality vs long-horizon session capability vs per-user experience — is a candidate refinement for the poetics rubric's whole-transcript scoring (`config/evaluation-rubric-poetics.yaml`), which currently grades dramatic form as one composite rather than separating "is this a good single scene" from "did this hold up across the whole session" from "did it work for this particular learner persona" (`services/learnerConfigLoader.js`).
