The documentation map

One web stack, six layers of record, two source formats, one design system — and the seams that need mending.

This repo writes a lot about itself: a canonical paper, sixty-five root documents, a schema-checked work board, three hundred working notes, nearly two gigabytes of run artifacts, and a family of web pages that read them all back. This map records how those pieces hang together — where each kind of writing lives, who declares what canonical, how the generated views get rebuilt, and which joints have worked loose. It was drawn from four read-only sweeps on 2026-08-05; each defect in the ledger at the end has a matching card on the work board under docs-*.

01·

Servers

One stack, three hosts, two strays.

Everything meant for the browser is a single Express route table, declared once in the shared mounter (services/evalSurfaces.js): the eval API, the pilot flow, A19 adjudication, human coding, tutor-stub sessions, the subject explorer, and the static UIs under public/. Three hosts mount that table:

  • The standalone server (server.js, npm start, port 8081) — loopback by default, HTTP basic auth plus a role gate in front of every route.
  • The poetics scriptorium (scripts/browse-poetics-scripts.js, port 3466) — about thirteen thousand lines of server-rendered pages (browse, read, derivation views, board, timeline, doc views) plus the /admin job launcher, with the shared surfaces mounted on top. npm run poetics:serve is a thin launcher that frees the port first, so a restart is one command.
  • The desktop app — Electron forks the same poetics app factory onto an ephemeral loopback port and points its window at it.
i.

Route drift cannot merge by construction

Web and desktop serve the same table because they call the same factory, and a parity test compares the served routes. The sync is enforced, not promised.

Two servers sat outside the stack. scripts/browse-transcripts.js (port 3456) was a 3,300-line second transcript browser with no npm script, no auth guard, a listener on every network interface, and a hardcoded path to the production database — retired 2026-08-05 in favour of the scriptorium. scripts/serve-subject-explorer.js (port 4505) duplicated a surface the main stack already serves, with the same open bind — rewritten the same day: loopback by default, the shared guard, and an npm script.

Auth is three mechanisms: basic auth with a role gate at the perimeter, a pilot admin token header, and the A19 coder key whose keyed mode switches on when a roster file exists. The perimeters differed by host until 2026-08-05: the standalone server guarded everything while the poetics server guarded only /admin, /tutor and the tutor-stub API, leaving the paid run endpoints under /api/eval open on a credentialed bind. Closed on the coherence branch: the poetics host now guards the shared eval surfaces from the same exported prefix list the mounter uses, while its reading pages stay public.

Note npm run chat is a terminal client of the 8081 server, not a server. The voice bridge is a token-gated side-car of the tutor-stub CLI, loopback and ephemeral.

02·

Layers

Six layers of record, by status.

  • Agent instructions. CLAUDE.md, AGENTS.md, GEMINI.md — the same project memory cut three ways, plus the style rule a hook injects on every turn.
  • Repo root, 65 files. Mostly frozen plans and pre-registrations — a status line in the first three lines is the house convention — plus theory notes that originate no claims, README / CONTRIBUTING / DEPLOYMENT, and the 185 KB TODO.md archive.
  • docs/. Operational reference (the script registry pairs with the analysis toolkit guide) and research. docs/research/paper-full-2.0.md is canonical for every empirical claim; paper-full.md is the legacy 1.0; the atlas is a generated projection of the paper.
  • workplan/. 397 schema-checked item files as source of truth; BOARD.md and board.json are generated views written only by the CI job on main. At 91% done the board is more archive than queue.
  • notes/. 296 files of design history — no frontmatter, loose Date: lines. notes/poetics/ is the biggest and also hosts the techne design system itself; daily notes are HTML research roundups with their own six-rule convention.
  • exports/. 1,900 files and 1.7 GB of run artifacts and analysis reports, some cited by the paper.

The status taxonomy is carried in the files themselves — frozen status lines, "generated, do not edit" banners, a JSON schema on the board items.survey · 2026-08-05

Drift Two dating conventions coexist: board items carry schema-checked created: / updated: frontmatter; notes carry a loose prose Date: line. Nothing bridges them.

03·

Authority

Who rules what.

CLAUDE.md is the hub. It names one authority per question:

  • Empirical claims, numbers, tables — docs/research/paper-full-2.0.md; spin-offs inherit and may not originate claims.
  • Live work — workplan/items/; every change reaching main names its card.
  • Cell architecture — config/tutor-agents.yaml, never a doc's summary table.
  • Database schema — the migrations at the top of services/evaluationStore.js.
  • Analysis scripts — the registry scripts/ANALYSIS-SCRIPTS.md, with docs/analysis-toolkit-guide.md as the workflow layer.
  • UX and desktop — desktop/ARCHITECTURE.md: one UI codebase, never fork into desktop/.
  • Prose — .claude/style-rule.md, injected every turn.

The paper cites about thirty root plan and pre-registration documents as provenance, which pins them in place: a closed experiment's plan is citable history, not clutter. The weak spots are the pointers into the live present: the fork's named master plan calls itself historical, the June "canonical active plan" is dormant, and the August plan closed and handed off to notes plus board cards — so no root document names the current arc. DEPLOYMENT.md and the house-style doc are near-orphans, linked from almost nothing.

Pinned Frozen pre-registrations are edited only with dated editor's notes, if at all — the paper cites them at specific commits. Grep the paper before moving or deleting any root doc.

04·

Design

Two source formats, one design system, a tail of one-offs.

The working rule: markdown when a document is prose; hand-authored HTML when it needs components — and for techne docs the HTML is the source, with no build step. Design lives in notes/poetics/assets/techne.css, behaviour in techne.js, and every JS feature is opt-in by markup.

One visual system — warm paper and ink; Fraunces, Source Serif 4, JetBrains Mono — with two sanctioned skins: data-skin="machine-spirits" (the website's white and red Swiss face, used by the two published pieces) and data-skin="stark" (dashboard framing). The app UIs under public/ share the palette; the pilot pages swap the face to Inter. The scriptorium and the techne docs are genuinely one system.

Two copies of the tokens exist: the full editorial stylesheet in notes/poetics/assets/ and an 11 KB served subset at public/components/techne.css. They are synced by comment, not by test, and the light paper token already differs between them. Five one-off visual systems linger in docs/ from before the house style — a teal guide, a navy interactive index, a rounded-card spec, a pasted critique, and the mermaid diagram pages.

Rule The operational/editorial split is written down in docs/design/machinespirits-house-style.md: Swiss white-field chrome for transcripts and tools, parchment techne for essays and atlases.

05·

Regeneration

From source to site.

Each generated view has exactly one writer, but the writers are scattered:

  • Board views — scripts/workplan.js render; on main only the serialized CI job commits them, and feature branches must not.
  • Reference status — npm run refs:render writes docs/ref-status.md; refs:check fails when stale.
  • Paper — docs/research/build.sh (pandoc + xelatex); the bare default now builds the canonical paper2, and full announces itself as the legacy 1.0. npm run docs:prune-pdfs applies the keep rule to the versioned PDFs beside the sources.
  • Atlas — scripts/build-atlas.js projects the paper into spine and module PDFs; it never edits the paper.
  • Arc images and regions — npm run poetics:arc-html rewrites marked regions of the arc doc.

Deployment is deliberate and human-gated: the publish scripts stage standalone HTML, PDFs and images into the sibling content repo (../machinespirits-content-philosophy/articles/ai-tutor/), and only its ./publish pushes — a GitHub Action then redeploys the site. Live URLs sit under /content/articles/ai-tutor/, and pages are checked by content, not status code, because unknown routes soft-200.

Added One verb now exists: npm run docs:refresh runs the cheap regenerations and reports what changed; the paper PDF stays a separate, LaTeX-heavy step.

07·

Target shape

What done looks like.

  • One entry point. A root index that reaches every layer in one hop — paper, board, notes, exports, servers, deploy — and names the live arc.
  • Statuses you can trust. Every document declares itself canonical, frozen, generated or note, and the declarations are current.
  • No unguarded doors. Every listener binds loopback by default and shares the one auth perimeter.
  • One refresh verb. A single command rebuilds the generated views and says what changed; deploy stays human-gated.
  • Tested seams. The token mirror, the route parity, the board views and the reference status all fail loudly when they drift — no sync-by-comment.

Method Doc-only repairs land first; server and build changes ride their own cards with tests. Frozen documents get editor's notes, never rewrites.
